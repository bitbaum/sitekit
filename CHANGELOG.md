## Unreleased

- The application chrome sets its own box model. Found 2026-11-12 rendering the shell on a page without a `box-sizing: border-box` reset: the masthead row was 422px wide on a 390px screen and the controls about 67px tall. `styles.css` now gives sitekit's own elements in the masthead, footer, tab bar and skip link `box-sizing: border-box` at zero specificity (`:where(…)`), so a host reset, or any host rule with a type, class or id selector, still wins; a host rule on `*` alone loaded before `styles.css` loses on source order. Host content passed into a slot (`brand`, `actions`, a footer's `extra`, a tab `icon`) is left out and keeps the host's box model; pseudo-elements are not covered. A link put straight into `actions` loses its block padding (`padding: 0 1rem`, was `0.65rem 1rem`): it is 44px tall under `border-box` as before (unless its text line is taller than about 21px) and 46px under `content-box`, where it was 67px. Checked in a browser at 320 and 390px with and without a host reset (no sideways scroll, every menu button and action 44–48px tall), and that a 100px host element in each slot still measures 124px, as outside the chrome (`test/box-model-browser.test.js`).
- Nav items that link elsewhere. Found 2026-11-12: a nav could not point at `https://github.com/bitbaum` (`href()` made it `/https://github.com/bitbaum`). The rendered nav props (`SiteMasthead` `navItems` and `navGroups`, `SiteNav` `items` and `groups`) now take `SiteNavLink`: an in-site `path`, or an `href` used verbatim, exactly one of them. An `href` must start with `http:`, `https:`, `mailto:`, `tel:`, `//`, `#` or `?` (`isAllowedHref`); the new `siteNavLinkSchema` refuses anything else (`javascript:`, `data:`, `vbscript:`, `bitcoin:`, `lightning:`, any other scheme, in any letter case or after leading whitespace) and both-or-neither, each with a message on the `path` or `href` field, and the renderers leave such an item out. The schema's output type is `SiteNavLink`, so a parsed item can be passed straight to `SiteNav` or `SiteMasthead`. Items are filtered before they are counted, so a nav or group whose every item is refused renders as one given none: no application nav, menu or group heading, and in the document appearance the same empty `<nav>` that `items={[]}` renders. `href()`, `siteNavItems()`, `SiteNavItem`, `siteNavItemSchema` and `SiteNavGroup` are unchanged: a `path` is always an in-site path, joined exactly as in 0.7.0 whatever it contains (`notes:2026` → `/notes:2026`). New exports: `siteNavLinkSchema`, `SiteNavLink`, `isAllowedHref`, `isExternalHref`, `navItemHref`, `isCurrentNavItem`, `HrefOptions` (root) and `SiteNavLinkGroup` (react). `test/types/consumer.ts`, compiled by `typecheck`, holds a 0.7.0 consumer's code (`siteNavItems(pages).map((i) => i.path.length)`).
- `rel="noopener"` on links to another origin in the nav and the footer, decided as a browser resolves the link against an http or https page: `https://…`, `//…`, and forms a browser reads the same way (`https:/\host`, `/\host`, `\\host`). This changes existing footer markup: a footer link such as `https://x.ch` now renders with `rel="noopener"`. A footer link with a `javascript:`, `vbscript:` or `data:` scheme (read as a browser reads it: any letter case, after leading spaces or control characters, with tabs or line breaks inside) is no longer rendered, and a footer group whose every link is dropped is left out with its heading (a group given no links renders as in 0.7.0); every other footer link (`/roadmap`, `mailto:`, `bitcoin:`, `lightning:`, any other scheme) renders as in 0.7.0.
- `trailingSlash` on `SiteMasthead`, `SiteNav`, `SiteTabBar` and `href(path, { trailingSlash: true })`, for a static site that serves each page as a directory: `/work/`, the slash before a `?query` or `#fragment` (`/a/#b`, `/a/?b`), none after a last segment with a file extension (`/feed.xml`) unless the path already ended in a slash (`/a/b.c/` stays), `''` and `/` give `/`. With it, `aria-current` matches `currentPath` with or without slashes at either end (`/work/` marks `work`). Without it, nothing changes for 0.7.0 consumers: `href(path)` is byte-identical for every input (a table of 26 tested), and `aria-current` is set only when `path` equals `currentPath` exactly, so `currentPath="/work"` still marks nothing. Checked by `test/links.test.js`; masthead, nav and tab bar markup for path-only items was compared with the 0.7.0 build (static and string render, seven `currentPath` values) and is identical, except that a nav `path` a browser reads as another host (`\\host`, `/\host`) keeps its 0.7.0 `href` and now also gets `rel="noopener"`; tab bar markup is identical without exception.
- `SiteFooter` `year`. Found 2026-11-12: the footer printed `new Date().getFullYear()` during render, so a statically generated page changed on 1 January. Pass `year={2026}` to print that year without reading the clock, or `year={null}` to print none. Omitted, or anything other than an integer from 1 to 9999 (`0`, `NaN`, `1e21`, a string from an untyped caller), the application footer reads the clock as before; the document footer prints no year and does not read the clock. Checked with the clock set to 2026-12-31 and 2027-01-01 (`test/footer-year.test.js`).
- `SiteIcon` and `SITE_ICON_NAMES`: one stroke icon set on `currentColor` (home, write, search, compass, star, user, chat, bell, settings, list, globe, book, heart, plus, menu, calendar, wallet, chart) for tab bars and account actions, so products stop passing unicode glyphs that render differently on every phone.
- `SiteTabBar` look: equal cells in a grid, a 24px icon box (SVG or glyph), 11px/600 labels, the current tab marked by a short rule above its icon and full text colour instead of a fill, 56px cells with the safe-area inset outside them.
- `SiteMasthead` `tabBar` prop: when the page also renders a `SiteTabBar`, the masthead drops its menu button below 48rem — the tab bar is the navigation there — and keeps the account actions in the row.
- `SiteTabBar`: a mobile bottom tab bar (3–5 items, icon + label, nested-path current state, safe-area aware), hidden from 48rem up. First consumer: BiasLens.
